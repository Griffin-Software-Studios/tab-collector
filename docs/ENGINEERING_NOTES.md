# Engineering Notes

## Current architecture summary

The extension is currently organized into four main runtime surfaces:

- `background.js`
  service-worker orchestration, storage writes, save, restore, commands,
  omnibox, and context menus
- `popup.js`
  quick-action and selected-tab save UI
- `collector.js`
  saved-group management UI
- `shared.js`
  defaults, storage shape, normalization helpers, and display utilities

## Important browser/platform constraints

### Native tab-strip context menus are not available to the extension

The extension can add items to the page context menu, but not directly to the
native tab-strip or tab-group-header context menus. That is why the recent
`Save tab group` addition lives in:

- the page context menu
- the popup quick-action surface

instead of the built-in Edge tab-strip menu.

### Manifest V3 background behavior

- the background script is a service worker
- routing should stay explicit and resilient to worker restart
- state should live in `chrome.storage.local`, not implicit globals

### Save privacy posture

Saved data currently includes:

- tab title
- tab URL
- favicon URL when available
- optional group notes entered by the user

There is no remote sync or server dependency in this repository today.

## Current design decisions

### GSS/Griffin styling

The options page and collector page now use Griffin/GSS-inspired theme tokens.
This is a presentation system, not a separate design framework dependency.

### Named themes plus appearance modes

The theme model now uses two settings instead of one:

- `theme`
  selects the named palette
- `themeMode`
  selects the appearance variant when that palette supports one

Current state:

- Griffin supports `system`, `light`, and `dark`
- Cobalt, Ember, and Forest are imported and currently keep their authored
  dark/base palette
- collector and popup surfaces use the shared theme application helper

### Save semantics

- window save prefers highlighted tabs first
- then the active browser tab group
- then the full window

This gives the popup and toolbar behavior a native-feeling shortcut path while
still allowing exact tab selection from the popup.

## Known cleanup targets

### Naming convergence

The main action surfaces now use `save` terminology consistently for:

- toolbar-action setting values
- popup action IDs
- context-menu IDs
- the keyboard command name
- runtime message types
- internal save pipeline functions

The project now uses explicit registries in `shared.js` to define these
contracts, which reduces string drift across `background.js`, `popup.js`, and
the docs set.

### Documentation depth

The new docs set is a first pass. It still needs:

- deeper collector function documentation
- a documented screenshot replacement process
- release and store-submission checklists

### Testing

The repo now includes a lightweight Node-based automated test suite.

Current automated coverage includes:

- shared normalization and helper behavior
- manifest/HTML/JS contract alignment for action and command IDs
- save-action registry integrity across popup and background wiring
- extracted background save-selection/save-filtering behavior
- extracted collector summary, restore-behavior, and focus-navigation logic

Current verification still depends partly on manual browser validation for:

- collector page interactions
- popup interaction flow inside Edge
- context-menu behavior in a live extension session
- tablet/mobile sizing behavior under real browser resize

Repo-local Edge evidence is generated by:

- `node tests/manual/capture-edge-evidence.js`
- `node tests/manual/verify-edge-evidence.js`
- `tests/manual/EDGE_RELEASE_CHECKLIST.md`
- `tests/assets/screenshots/`

The evidence script now captures collector screenshots at desktop, tablet, and
mobile viewport sizes in addition to popup and options surfaces.
